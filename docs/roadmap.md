# План разработки

Документ задаёт порядок работ: что делаем, в какой последовательности и по каким признакам этап считается
завершённым. Этапы идут строго по очереди — каждый следующий опирается на предыдущий.
Отметки `[x]` ставятся по мере выполнения.

## Как ведётся каждая задача

1. **Правило.** Если задача меняет поведение — сначала обновляется спецификация в `docs/`
   (для движка — `docs/engine/`), затем код.
2. **Макет.** Новый экран или заметное изменение интерфейса — сначала PNG-макет, согласование, затем код.
3. **Ветка.** Работа ведётся в отдельной ветке от `main`. `main` — это опубликованный сайт.
4. **Код и тесты.** Движок — чистые функции с тестами по сценариям; интерфейс — сценарий в Playwright (WebKit).
5. **Проверка.** WebKit-сценарий без ошибок, затем — на iPhone с экрана «Домой», в тёмной и светлой теме.
6. **Публикация.** Слияние в `main` только после согласования → GitHub Actions публикует сайт автоматически.

### Признаки готовности любой задачи
- `npm run build` проходит (TypeScript strict), тесты зелёные, в консоли нет ошибок.
- Экран продуман в состояниях: первый запуск, пусто, загрузка, ошибка, много данных.
- Работает без интернета, не теряет введённые данные при закрытии приложения.
- Зоны нажатия не меньше 44 pt, контраст AA, подписи для VoiceOver.
- Тексты соответствуют правилам ниже.

## Тексты интерфейса

- Официальный нейтральный стиль: коротко, точно, без разговорных и жаргонных слов («норм», «добираем», «качалка»).
- Предпочтительны безличные формулировки: «Вес увеличен на 2,5 кг», «Упражнение завершено».
  Если нужно обращение — на «Вы».
- Без восклицательных знаков и эмодзи в интерфейсе.
- Единые термины: подход, повторения, вес, запас повторений, разминка, отдых, тренировка, упражнение.
- Кнопки называют действие: «Начать тренировку», «Подход выполнен», «Пропустить».
- Объяснения движка («почему») — констатация факта и решения: «Спина не получала нагрузку 6 дней».
- Числа — с единицами и русским форматом: 62,5 кг · 6 340 кг · 1:24.
- Все строки хранятся в одном словаре (`src/ui/strings.ts`), а не в разметке экранов.

## Технологии

- Vite + TypeScript (strict) — **принято**.
- Деплой: GitHub Actions → GitHub Pages, `https://curstfear.github.io/Balance/` — **работает**.
- UI-фреймворк — **требует решения** на этапе 0. Рекомендация: **Svelte 5** — минимальный размер,
  встроенные переходы и анимации, высокая скорость на iPhone. Альтернатива — Preact.
- Dexie (IndexedDB), vite-plugin-pwa (офлайн и обновления), Vitest (движок), Playwright с WebKit (сценарии).
- Структура: `src/engine` (чистая логика без UI и БД), `src/data` (БД, каталог), `src/ui` (экраны и компоненты), `docs/`.
- Статус-бар на iPhone — `default` + `theme-color`. `black-translucent` в iOS 26 оставляет
  неотрисованную полосу внизу экрана, использовать нельзя.

- [ ] Схема Dexie версии 1: профиль, залы, тренировки, упражнения тренировки, подходы, замеры, настройки.

продолжается с того же подхода; миграции проходят тесты.

## Этап 2. Каталог

Цель: основа качества тренировок. Состав — [engine/catalog.md](engine/catalog.md).

- [ ] Мышцы и паттерны движений.
- [ ] Оборудование с изображениями — для выбора «Мой зал».
- [ ] 100–150 упражнений с разметкой: паттерн, вклад мышц, противопоказания, замены, шаг веса.
- [ ] Изображения техники в едином плоском стиле + 2–3 подсказки к каждому упражнению.
- [ ] Проверка каталога владельцем.

**Готово, когда:** каждое упражнение имеет полную разметку, изображение и подсказки; каталог согласован.

## Этап 3. Движок тренировок v1

Цель: сборка тренировки и подстройка по ходу. Правила — [training-engine.md](training-engine.md) и `docs/engine/`.

- [ ] Конфиг движка — зеркало [engine/config.md](engine/config.md).
- [ ] Конвейер: допуск → контекст → состояние мышц → сборка → назначение весов → проверка лимитов.
- [ ] Живая подстройка следующего подхода по повторениям, весу и запасу повторений.
- [ ] Замены: «тренажёр занят», «не предлагать», боль.
- [ ] Коды причин и их тексты («почему») по правилам текстов.
- [ ] Возврат после перерыва, режим новичка, смещение оценки запаса повторений.
- [ ] Все сценарии из [engine/test-scenarios.md](engine/test-scenarios.md) покрыты тестами.

**Готово, когда:** все сценарии проходят, финальная проверка лимитов срабатывает на каждой собранной тренировке,
у каждого упражнения есть объяснение.

## Этап 4. Онбординг и «Мой зал»

Цель: новый пользователь за 2–3 минуты получает персональный план. Сценарий — [product.md](product.md), раздел 1.

- [ ] Макеты всех шагов → согласование.
- [ ] Шаги: данные тела, опыт, цель, приоритетные зоны, частота и длительность.
- [ ] Опрос здоровья и согласие с отказом от ответственности; блокировка или осторожный режим — по [engine/safety.md](engine/safety.md).
- [ ] Ограничения по зонам и степени.
- [ ] «Мой зал»: пресеты, выбор оборудования по изображениям, шаги весов, несколько залов.
- [ ] Итоговый экран: структура недели и кнопка «Готово».

**Готово, когда:** человек без объяснений проходит онбординг и получает первую тренировку.

## Этап 5. Тренировка — основной сценарий

Цель: полный цикл в зале на реальных данных. Сценарий — [product.md](product.md), раздел 2.

- [ ] «Сегодня» на реальных данных: неделя, следующая тренировка, «Баланс недели», готовность.
- [ ] Чек-ин перед тренировкой (можно пропустить).
- [ ] План: замена, удаление, добавление упражнения; изменение длительности.
- [ ] Подход: ввод веса и повторений, запас повторений, кнопка «Боль», экран «Стоп» с тревожными признаками.
- [ ] Отдых: таймер со звуком и вибрацией, экран не гаснет, подстройка следующего подхода.
- [ ] Разминочные подходы перед первым тяжёлым упражнением.
- [ ] Итог: время, тоннаж, рекорды, изменение баланса, оценка нагрузки.

**Готово, когда:** выполнена первая реальная тренировка в зале без единой ошибки.
→ **Контрольная точка: тестирование в зале.** Сначала владелец (2 недели), затем 2–3 знакомых.
Замечания собираются в список и разбираются до перехода к этапу 6.

## Критерии готовности MVP
- Новый человек без объяснений проходит онбординг и первую тренировку.
- 4 недели реальных тренировок: веса растут, мышцы нагружаются равномерно, нет абсурдных тренировок.
- Ничего не теряется при закрытии приложения, перезагрузке телефона и обновлении приложения.
- Приложение работает в зале без интернета.

## Принятые решения
- Техника упражнений — изображение и 2–3 подсказки, **без видео**.
- Синхронизации между устройствами **не будет** — только резервная копия и импорт.
- Перед кодом — макеты ключевых экранов.
- Каталог упражнений готовит Claude, владелец проверяет.
- Программы для мужчин и женщин отличаются только приоритетами по умолчанию, шагами веса и отдыхом
  (см. engine/load-and-progression.md §9).
- Дизайн: плоский, без бликов; свечение допускается только на карточках с иллюстрацией.
- Тексты интерфейса — официальный нейтральный стиль (раздел «Тексты интерфейса»).

## Открытые вопросы
1. UI-фреймворк: Svelte 5 (рекомендация) или Preact — решить в начале этапа 0.
2. Как быстрее всего вносить зал: каталог с изображениями или дополнительно фотография тренажёра (позже)?
3. Стиль изображений техники: плоские иллюстрации в цветах мышц — подтвердить макетом на этапе 2.
4. До кода движка сверить с первоисточниками числа, помеченные в training-engine.md.
