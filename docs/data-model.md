# Модель данных

Хранилище — IndexedDB (через Dexie). Всё локально, на одном устройстве, у каждого пользователя своё.
Принцип: **храним сырые факты, производное вычисляем** (готовность мышц, объёмы, рекорды, 1ПМ).

## Сущности

**Profile** (одна запись)
пол, дата рождения, рост, опыт, цель, приоритетные мышцы, тренировок в неделю, минут на тренировку,
единицы, дата онбординга, настройка суперсетов (авто/всегда/никогда), смещение RIR (bias) + дата калибровки.

**HealthScreen** — ответы опроса здоровья (история, повтор раз в 12 мес)
дата, ответы[9], результат (ok / cautious / blocked), «врач разрешил» + дата, согласие с дисклеймером + дата,
беременность (срок по датам) / после родов.

**Limitation** — ограничение
зона, степень (иногда / обострение / после операции), с какого числа, до какого (для временных), источник (онбординг / чек-ин / боль в тренировке).

**PainEvent** — эпизод боли
дата, workoutId?, exerciseId?, зона, тип (крепатура / сустав / острая), сила (ок / терпимо / острая), «утром после» (лучше / так же / хуже).

**ExercisePref** — предпочтения (или вычислять из истории замен)
exerciseId, «не предлагать», ручные отметки.

**BodyMetric** — замеры во времени
дата, вес, % жира?, обхваты (талия, грудь, бедро, плечо…)?

**Gym** — зал пользователя
название, список id оборудования, страховка (рама/упоры), шаги веса (ряд гантелей, шаг стека тренажёров,
мелкие блины 1.25/0.5), по умолчанию да/нет.
Якоря мезоцикла и рабочие веса тренажёров/блоков — **по залу** (`(exerciseId, gymId)`), штанга и гантели — общие.

**Equipment** — каталог (поставляется с приложением)
id, название, тип (штанга, гантели, блок, рычажный тренажёр, свободный вес тела…), картинка.

**Exercise** — каталог + пользовательские. Полная схема — [engine/exercise-selection.md §1](engine/exercise-selection.md).
Каталог встроенный и версионируется вместе с приложением; пользовательские хранятся в БД.

**Mesocycle**
начало, конец?, номер недели, якоря `{gymId: {pattern: exerciseId}}`, пары дополняющих A/B, разгрузка да/нет.

**Workout** — тренировка
id, зал, начало, конец?, статус (план / идёт / завершена / брошена), чек-ин (сон, самочувствие, болезнь, зоны),
режимы на момент сборки (новичок, cautious, возврат, разгрузка), версия движка, seed, заметка, оценка.

**WorkoutExercise**
workoutId, exerciseId, порядок, коды причин `[{code, params}]`, целевые подходы/повторы/вес/RIR,
заменило exerciseId? + причина (занято / не хочу / боль), пропущено?, суперсет-группа?

**Set** — подход (главный сырой факт)
workoutExerciseId, номер, тип (пристрелка / разминка / рабочий / до отказа-калибровка), вес, повторы,
RIR названный (поправленный — вычисляется), боль (нет / терпимо / острая), время выполнения, отдых до него.

**Settings**
тема, звук/вибрация, напоминание о бэкапе, дата последнего бэкапа.

## Правила
- Подход сохраняется сразу после ввода (тренировка переживает закрытие приложения).
- Схема версионируется; каждая миграция — с тестом на данных предыдущей версии.
- Каталог упражнений обновляется с приложением; id стабильны, удалённые из каталога упражнения
  остаются читаемыми в истории.
- В тренировке хранится версия движка — чтобы позже понимать, по каким правилам она собрана.

## Хранение на iPhone и бэкап
- Safari может удалить данные сайта, которым давно не пользовались. Поэтому:
  просим установить на экран «Домой» (подсказка с инструкцией), вызываем `navigator.storage.persist()`.
- **Бэкап**: экспорт всей БД в JSON → шифрование WebCrypto (AES-GCM, ключ из пароля через PBKDF2) → файл
  через «Поделиться» (Файлы, iCloud, Telegram). Импорт — с проверкой версии и предпросмотром «что заменится».
- Напоминание о бэкапе раз в 2 недели, если были новые тренировки.
- Перенос на новый телефон = экспорт → импорт.
